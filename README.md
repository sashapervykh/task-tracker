# Список задач

HTTP API для личного списка задач. Сервис нужен одному человеку: добавить задачу, посмотреть список, отметить выполненное и удалить. Интерфейса в браузере нет, кроме автоматической страницы документации.

Список хранится в памяти процесса. После остановки приложения задачи пропадают, база данных не используется.

## Подготовка

Команды выполняются в каталоге `task-tracker`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env
```

`.venv` — отдельное окружение этого проекта. Пока в приглашении оболочки есть `(.venv)`, `python` и `pip` ставят пакеты сюда, а не в системный Python. В новом терминале окружение нужно включить снова.

Файл `.env` остаётся на машине и в git не попадает. В репозитории лежит только образец `.env.example`.

## Запуск

Без `--reload`, из того же каталога и с включённым `.venv`:

```bash
set -a && source ./.env && set +a
python app_final.py
```

В zsh путь `./.env` обязателен: без `./` оболочка ищет файл в `PATH`. `set -a` передаёт переменные из файла процессу.

Сервер слушает `127.0.0.1`. Порт берётся из `PORT`, если переменная не задана — `8000`. В образце `.env.example` указан порт `8000`, тогда адрес сервиса `http://127.0.0.1:8000`.

Документация маршрутов открывается в браузере: `http://127.0.0.1:8000/docs`. Если в `.env` другой `PORT`, подставьте его в адрес.

Остановка — `Ctrl+C` в терминале, где запущено приложение.

## Проверка

В другом терминале, при порте `8000`:

```bash
curl -s http://127.0.0.1:8000/health
curl -s http://127.0.0.1:8000/version
```

Ожидаемые ответы: `{"status":"ok"}` и `{"version":"0.1.0"}`. Версия в ответе совпадает с `APP_VERSION`.

## Тесты

Из каталога `task-tracker`, с включённым `.venv`:

```bash
python -m pytest -v
```

Ожидаемый результат: все тесты в `test_app.py` проходят.

## Переменные окружения

| Переменная | Назначение | Если не задана |
| --- | --- | --- |
| `APP_NAME` | Имя в ответе `GET /` | `task-tracker` |
| `APP_VERSION` | Версия в ответе `GET /version` | `0.1.0` |
| `LOG_LEVEL` | Уровень сообщений приложения | `INFO` |
| `PORT` | Порт при запуске `python app_final.py` | `8000` |

Паролей и токенов в этих переменных нет.

## Логи

Сообщения приложения пишутся сразу в два места: в терминал, где оно запущено, и в файл `logs/app.log` в каталоге `task-tracker`. Папка создаётся при запуске. Файл можно открыть в редакторе, не останавливая сервер: новая строка появляется сразу.

Туда попадают запуск и версия сервиса, остановка, запрос списка и одной задачи, создание, отметка выполненной и удаление. В строке есть номер задачи или число найденных задач и результат. Туда же попадают ошибки: неверные данные, неизвестная задача, сбой при обработке запроса.

Уровень задаёт `LOG_LEVEL`. Если указано неизвестное значение, сервис пишет предупреждение и использует `INFO`.

Каталог `logs/` в git не входит. Тесты тоже дописывают строки в `logs/app.log`.

Строки uvicorn о процессе и о каждом HTTP-запросе видны в терминале. При запуске через `python app_final.py` они дополнительно попадают в тот же файл.
